# Battle Scissors

A 2D mobile canvas game prototype built around one mechanic: two fingers are the handles of a pair of scissors, and a fast pinch snips whatever sits between the blades.

## Running

Double-click `Play.bat`, or run:

```bash
node tools/serve.js
```

It serves on port 8000 on all interfaces, opens http://localhost:8000 (with `--open`), and prints a LAN address for testing on a phone on the same Wi-Fi. If 8000 is busy it moves up to the next free port (8001, 8002, ...). `python3 -m http.server` also works. ES modules don't load from `file://`, so opening `index.html` directly shows a "use Play.bat" message. Desktop controls (mouse, wheel, Space, A/D rotate, E = SHRED, P/Esc = pause, R) are listed at the top of `index.html`. `?seed=1234` pins the run seed (the run report's replay link uses it).

Shared runtime state lives in exported objects (`state` in game.js, plus `input`, `view`, `weapon`, `cut`), because ES modules can't reassign each other's `let` bindings. `state` holds the mode, wave, HP, score, seed, stats, effect timers (`state.fx`), the road polyline (`state.path`), the thread balance, `heli` (special), `tut` (onboarding step), `run` (report counters), `events` (a 32-entry ring of one-off happenings for the renderer: `thread` pickups, `place`) and the entity pools (`enemies`, `frags`, `parts`, `labels`, `nums`, `pops`, and `towers`, one per level spot): plain objects with an `on` flag and no methods. Each frame, `update()` calls `updateInput()` first, so snips resolve before timers and entities advance; then `draw(state)` paints.

**game.js contains no canvas calls. All drawing lives in render.js. This keeps a future Phaser/Godot port cheap.** (render.js calls the art helpers enemyArt.js, towerArt.js and weaponArt.js; game.js, input.js and scissors.js never draw.)

Seeds: every run gets `state.seed` (`Date.now()` by default; `?seed=1234` in the URL pins it for every run). Gameplay randomness uses mulberry32 streams from that seed: `rng.spawn` (enemy variation), `rng.hit` (shove chance), `rng.fx` (fragment bursts). They're separate so spawns don't depend on how many hits happened. Only purely visual sparkle (particles) may use `Math.random`. The seed shows in the debug panel and on the game-over card.

## Game flow

`TITLE -> SELECT -> [TUTORIAL] -> PLAYING -> WAVE_CLEAR (waveClearMs) -> PLAYING ... -> GAME_OVER`. On the title, PLAY opens the weapon SELECT screen (START begins, BACK returns); How to play replays the TUTORIAL; the Sound icon toggles mute; Upgrades, Shop and Settings are placeholders (`data-soon`) that show a "coming soon" message. The TUTORIAL runs on the first START (flag `battleScissors.onboarded` in localStorage): grip, spread, pinch fast on 3 pinned Scraps, a slow close, rotate, "Go.", then wave 1 with a fresh seeded run. Each step has skip links. Prompts have touch and desktop wordings (desktop: hold/release the button, the wheel for the slow close, A/D to aim); a too-fast close on the slow-close step shows a "Too fast!" nudge. GAME_OVER covers both outcomes: losing (workshop HP hits 0) and winning (after the last entry in `CONFIG.waves`), shown with different headers. Pause (`state.paused`, not a mode; `state.pauseCard` = `menu` or `pins` picks which card shows): the ⏸ button, P/Esc, or hiding the tab during PLAYING / WAVE_CLEAR / TUTORIAL. `update()` returns immediately while paused (no input, timers, tweens or clock), event-driven hooks (taps, E, Space) are ignored, paused time is excluded from the run duration, and resuming re-arms snip detection. The pause card offers RESUME, Sound on/off, Quit to title, Copy run report (an `inProgress` report, not saved) and Send feedback. Quit to title, the game-over Reset (home) tile and the R key return to TITLE; START and Play Again call `startGame()` with the current weapon.

- Title screen: `CONFIG.titleWeapon` (the War Nippers) is drawn at its in-game size following the pointer (pivot `pivotOffsetPx` above it), leaning with sideways motion, resting `titleOpenFrac` open and snapping shut while pressed.
- Weapons live in `CONFIG.weapons`: SVG geometry (`viewW/viewH/pivotX/pivotY/bladeLen/maxOpenDeg`, taken from the art) plus gameplay (`reachFrac` = on-screen blade length as a fraction of screen height, `damageMult`). `view.S = reachFrac * weaponScale * H / bladeLen`. Blade opening, cut-zone width and reach, and blade-contact size all come from the current weapon. `maxOpenDeg` is half the cut zone's angle at full open; `aimOffsetDeg + aimOffsetOpenDeg × open` turns the whole art so an off-centre gap lines up with the aim (Ratchet Pruners). `kind: 'slide'` (Cigar Cutter): no pivot or blade angle; the cut zone is a circle of radius `bladeLen` at the hole, graded from its centre; closing blades don't shove; the boss seam line runs across the hole; SHRED reaches `spinLen`; the weapon card shows Hole and "guillotine" instead of Reach and Spread.

- Waves come from `CONFIG.waves`: one array per wave of `[type, count, atSec]` entries, with group members spaced by the type's `gapMs`. A spawn waits if the enemy pool is full. If every enemy is dead mid-wave, the wave clock skips ahead so the next spawn is at most `emptyWaveWaitSec` away (group spacing is untouched, since the skip only happens while the board is empty).
- Enemy types live in `CONFIG.enemyTypes`: scrap (groups, 1 HP), bolster (3 HP), brute (6 HP plus armor), seamRipper (boss). Snip damage is graded and must stay that way: `damageAtPivot` (2) down to `damageAtTip` (1), times the opening power (`powerAtMinOpen`..1), times `weakDamageMult` for a nick. So base HP equals snips needed at worst (a full-open snip at the tips). Each wave after the first scales every enemy's HP by `hpPerWave` (wave n = base × (1 + hpPerWave × (n − 1)); the tutorial's wave 0 uses base HP), so later enemies need hits nearer the pivot or an extra snip.
- Brute armor: the first snip clangs for 0 damage unless `e.slowed` is true (Ice Pin aura, or a recent Helicopter hit).
- Thread (tower currency): `startThread`, +`threadPerKill` per kill, +`threadPerLeak` when an enemy reaches the workshop.
- Towers ("Pins" in the UI; `CONFIG.towers`) set up snips; the Fire Pin is the one exception that deals damage (a slow burn). They can only stand on the level's spots (`CONFIG.level.spots`, one Pin each; `state.towers[i]` is spot i). Building: tap the + on an empty spot, then a card in the picker beside it. Radii are in level units (`towerReach(type)` = px). Ice Pin: enemies in its radius move at `slowSpeedMult` and are `slowed`. Fire Pin: enemies in its radius catch fire (`e.burning`, drawn with flames) and keep burning `burnSec` after leaving it, taking `burnDps` HP/s every `burnTickMs` (ignores armor; orange damage numbers). Burn kills score and pay thread but don't charge SHRED. Magnet Pin: every `periodSec`, tweens the road progress `u` of enemies in its radius toward the Pin's road point (`fu`), leaving `pullKeep` of the gap, so the ones ahead are dragged back and the ones behind hauled forward into a lasting clump (`e.pulling` while the tween owns `u`/`ox`/`oy`; inOutSine; tagged by the enemy so a kill cancels it).
- Helicopter special (SHRED): charged by `heliKillsToCharge` kills (not during a spin). Trigger: a third finger while gripping (anywhere, or on the SHRED card), or E. Its charge meter is the SHRED card in the action bar. Snaps open, spins `heliSpinTurns` turns, damages everything in blade reach every `heliTickMs` (ignores armor, slows), then snaps shut into a normal full-open snip. The hand moves the pivot but not spread or aim; normal snips are ignored while it runs.
- Run reports: `endGame` builds `lastReport` (seed, waves, score, snips, kills, accuracy, multi-snips, towers, specials, leaks, duration, userAgent, the six debug values, replay link) and saves it via runlog.js. No analytics or network calls; Send feedback only opens `FEEDBACK_URL` (a `mailto:` draft carrying the run report; nothing is sent without the player pressing Send in their mail app).
- Boss: walks to each `bossTurns` point, then to the workshop. A snip's normal graded damage is multiplied by `seamMult` if the closed-blade line (from the pivot along the aim, blade length) passes within `seamHitTolPx` of the rotating seam arc, otherwise by `offSeamMult`. It can't be shoved.
- Kills of tier 2+ trigger a whole-world hit-stop (`hitStopMs`, boss `bossHitStopMs`). Input keeps running through it. Every kill adds screen shake proportional to the enemy's radius. Both run on game.js's real-time tween group, and fragment fades on the world group; a frame is frozen if `fx.hitStop` was still > 0 when it started.
- The level is a painted plate (`CONFIG.level`): drawn full height and centred, so level units → screen px is `view.L = H / level.h`, offset `view.LX`. `level.path` (in plate pixels, traced along the painted road) is rebuilt into a Catmull-Rom polyline on resize. Enemy radii and weapon reach are still in screen px, not level units. Enemies store progress `u` (0..1) and advance at `1 / traverseSec`. Shoves are an offset (`ox`, `oy`) that springs back to the road at `pathReturnRate`, capped at `level.roadHalfWidth` from the centreline (`keepOnRoad`), so nothing can be shoved off the road.
- An enemy reaching the workshop deals its size `tier`. A kill scores the size's `score`, times `multiSnipMult` when the snip's zone held at least `multiSnipMin` enemies (survivors count toward that).
- Snips, too-slow shakes and blade contact only happen in PLAYING / WAVE_CLEAR / TUTORIAL.
- Sound: every sound is triggered from game.js through audio.js; the AudioContext is resumed on the first menu-button click.

## Rules

- **Never put a cooldown on the base snip; the player's fingers are the cooldown.**
- **All tunable numbers live in `src/config.js`, each with a one-line comment.** Modules read `CONFIG` at runtime, so the debug panel can change values live. Don't copy config values into module-level constants.
- **No npm, no bundler, no CDN. Third-party code is vendored into vendor/ with its license, and must be under 5KB each.** Plain ES modules via `<script type="module">`, no build step.
- **The scissors' cutting zone must never be occluded by the player's fingers; blades extend away from the finger midpoint.** The pivot sits `pivotOffsetPx` above the finger midpoint, and the blades point perpendicular to the finger line, away from the hand.

## Conventions

- Hot loop: no per-frame allocations. Entities are pooled (`on` flag); snip history is a typed-array ring buffer.
- Snip detection reads the raw finger spread; rendering reads the smoothed `pose`. A close that started wide open (≥ `snipOpenFrom`) but took longer than `slowLookbackMs` still reports "too slow" (tracked by `openPeak` in input.js) instead of being ignored.
- Debug panel: long-press the top-right corner for 1.5s. "Reset defaults" restores `config.js` values and clears localStorage. If feel seems off, check the panel for a stale override first.

## Known debt

A few effect timings/physics numbers predate the config rule and are still inline in `game.js` (fragment gravity 420, particle drag 0.93, kick decay 120ms, ring 300ms, label/number lifetimes, particle count 240). Move them into `config.js` the next time you touch that code.
