# Battle Scissors

A 2D mobile canvas game prototype built around one mechanic: the player's fingers work a pair of scissors that snip whatever sits between the blades. Touch has two control modes (Settings on the title): **Hold** (default, easy: hold one finger to open, lift to snip) and **Pinch** (two fingers are the handles, a fast pinch snips).

## Running

Double-click `Play.bat`, or run:

```bash
node tools/serve.js
```

It serves on port 8000 on all interfaces, opens http://localhost:8000 (with `--open`), and prints a LAN address for testing on a phone on the same Wi-Fi. If 8000 is busy it moves up to the next free port (8001, 8002, ...). `python3 -m http.server` also works. ES modules don't load from `file://`, so opening `index.html` directly shows a "use Play.bat" message. Desktop controls (mouse, wheel, Space, A/D rotate, E = SHRED, P/Esc = pause, R) are listed at the top of `index.html`. `?seed=1234` pins the run seed and `?level=fork` picks the level (the run report's replay link carries both). `?recipe=s,fork pin` plays a generated road (see Level generator below). The level lab, `/tools/level-lab.html` on the dev server, previews recipes.

Shared runtime state lives in exported objects (`state` in game.js, plus `input`, `view`, `weapon`, `cut`), because ES modules can't reassign each other's `let` bindings. `state` holds the mode, wave, HP, score, seed, stats, effect timers (`state.fx`), the road polylines (`state.paths`, one per route of the level), the thread balance, `heli` (special), `tut` (onboarding step), `run` (report counters), `events` (a 32-entry ring of one-off happenings for the renderer: `thread` pickups, `place`) and the entity pools (`enemies`, `frags`, `parts`, `labels`, `nums`, `pops`, `needles`, and `towers`, one per spot of the current level, rebuilt by `setLevel`): plain objects with an `on` flag and no methods. Each frame, `update()` calls `updateInput()` first, so snips resolve before timers and entities advance; then `draw(state)` paints.

**game.js contains no canvas calls. All drawing lives in render.js. This keeps a future Phaser/Godot port cheap.** (render.js calls the art helpers enemyArt.js, towerArt.js and weaponArt.js; game.js, input.js and scissors.js never draw.)

Seeds: every run gets `state.seed` (`Date.now()` by default; `?seed=1234` in the URL pins it for every run). Gameplay randomness uses mulberry32 streams from that seed: `rng.spawn` (enemy variation, and which route each enemy takes on a multi-route level; single-route levels draw nothing for it), `rng.hit` (shove chance), `rng.fx` (fragment bursts). They're separate so spawns don't depend on how many hits happened. Only purely visual sparkle (particles) may use `Math.random`. The seed shows in the debug panel and on the game-over card.

## Game flow

`TITLE -> MAP | SETTINGS | level 0 (TUTORIAL -> MAP), MAP -> SELECT -> PLAYING -> WAVE_CLEAR (waveClearMs) -> PLAYING ... -> GAME_OVER`. On the title, PLAY opens the level MAP (tap a numbered patch, or Random Quilt; BACK returns to the title), which opens SELECT for the weapon (it names the level; START begins, BACK returns to the map); How to play replays level 0; the gear opens SETTINGS (touch controls Hold/Pinch, Sound, Vibration; BACK returns); the Sound icon toggles mute; the title's Upgrades and Shop tiles are still placeholders (`data-soon`); the real Shop and Trophies open from the map's top-left row, beside the Buttons balance. Level 0 (TUTORIAL, see below) replaces the old text coach: PLAY opens it instead of the map until it has been cleared once. GAME_OVER covers both outcomes: losing (workshop HP hits 0) and winning (after the last entry in `CONFIG.waves`), shown with different headers. The card plays the results (results.js: stars, the Button tally by source, total, unlock reveal) and then shows CONTINUE (opens the MAP), Next level (on a win with a next patch, `nextLevelId()`, same weapon) and Play again. Pause (`state.paused`, not a mode; `state.pauseCard` = `menu` or `pins` picks which card shows): the ⏸ button, P/Esc, or hiding the tab during PLAYING / WAVE_CLEAR / TUTORIAL. `update()` returns immediately while paused (no input, timers, tweens or clock), event-driven hooks (taps, E, Space) are ignored, paused time is excluded from the run duration, and resuming re-arms snip detection. The pause card offers RESUME, Sound on/off, Quit to title, Copy run report (an `inProgress` report, not saved) and Send feedback. Quit to title, the game-over Reset (home) tile and the R key return to TITLE; START and Play Again call `startGame()` with the current weapon.

- Title screen: `CONFIG.titleWeapon` (the War Nippers) is drawn at its in-game size following the pointer (pivot `pivotOffsetPx` above it), leaning with sideways motion, resting `titleOpenFrac` open and snapping shut while pressed.
- Weapons live in `CONFIG.weapons`: SVG geometry (`viewW/viewH/pivotX/pivotY/bladeLen/maxOpenDeg`, taken from the art) plus gameplay (`reachFrac` = on-screen blade length as a fraction of screen height, `damageMult`, `openMs` = how long a held mouse button or Hold-mode finger takes to open it fully). `view.S = reachFrac * weaponScale * H / bladeLen`. Blade opening, cut-zone width and reach, and blade-contact size all come from the current weapon. `maxOpenDeg` is half the cut zone's angle at full open; `aimOffsetDeg + aimOffsetOpenDeg × open` turns the whole art so an off-centre gap lines up with the aim (Ratchet Pruners). `kind: 'slide'` (Cigar Cutter): no pivot or blade angle; the cut zone is a circle of radius `bladeLen` at the hole, graded from its centre; closing blades don't shove; the boss seam line runs across the hole; SHRED reaches `spinLen`; the weapon card shows Hole and "guillotine" instead of Reach and Spread.

- Waves come from `CONFIG.waves`: one array per wave of `[type, count, atSec]` entries, with group members spaced by the type's `gapMs`. A spawn waits if the enemy pool is full. If every enemy is dead mid-wave, the wave clock skips ahead so the next spawn is at most `emptyWaveWaitSec` away (group spacing is untouched, since the skip only happens while the board is empty).
- Enemy types live in `CONFIG.enemyTypes`: scrap (groups, 1 HP), runner (small and fast, 1 HP; from level 3), bolster (3 HP), brute (6 HP plus armor; from level 5), beetle (the Button Beetle, 10 HP, level 11: `fireImmune`, `flat` = no weak spot, every snip does tip damage; `ringExecute` = a Cigar Cutter snip with its centre in the hole kills it outright), and the bosses seamRipper, bruteKing, unstitcher. Early levels bring types in slowly with fewer waves (L1-L2 Scraps and Bolsters, 3 waves); each level file lists its own waves. Snip damage is graded and must stay that way: `damageAtPivot` (2) down to `damageAtTip` (1), times the opening power (`powerAtMinOpen`..1), times `weakDamageMult` for a nick. So base HP equals snips needed at worst (a full-open snip at the tips). Each wave after the first scales every enemy's HP by `hpPerWave` (wave n = base × (1 + hpPerWave × (n − 1)); the tutorial's wave 0 uses base HP), so later enemies need hits nearer the pivot or an extra snip.
- Brute armor: the first snip clangs for 0 damage unless `e.slowed` is true (Ice Pin aura, or a recent Helicopter hit).
- Thread (tower currency, in-level only, gone when the level ends): `startThread`, +`threadPerKill` per kill, +`threadPerLeak` when an enemy reaches the workshop.
- Buttons (meta currency, `CONFIG.meta`, meta.js; never converted to or from thread): stars 10/15/25 the first time each is earned; score bonus floor(score/100) capped at 10 per level (a run pays only what beats the level's best bonus, `bonusPaid`); achievements (achievements.js) once each; a world chest (three-star every level of a world, then tap it on the map: 100 + a cosmetic). Spent in the Shop: upgrades 150/300/600 per weapon (T1 +15% reach, T2 +20% close speed, T3 the weapon's `signature` stat +30%: Split Enders angle, War Nippers damage, Scrap Snippers crit (`critZone`/`critMult`), Ratchet Pruners jaw hold (`holdSec`: its hits hold regular enemies still), Cigar Cutter ring (`ringScale`), Dagger Shears all +10%), Sharpening (40, max 3, +50% snip damage for the next level, used up at its start), cosmetics (handle tint baked into the weapon art by weaponArt.js `setHandleTint`, blade glow drawn by render.js). `node tools/buttonsupply.js` prints the total supply (in README).
- Levels live in `src/levels/` (the 13 map levels, `meadow`, `fork`, `hem`, then ten recipe levels up to `lair`; plus `random`; `CONFIG.defaultLevel`), loaded only through `loadLevel`. `CONFIG.map` places them on the map. A level's `waves` and `startThread` default to CONFIG's (`levelWaves()` in game.js); `allowedPins` limits the picker. A win scores stars: 1 for clearing, +1 per `starRules` rule met (`noDamage`: nothing reached the workshop; `noSpecial`: no SHRED), recorded in the save and the run report. Painted ones (`meadow`, `fork`) have `paths` (one or more routes, each walked first to last point, all ending on the heart pad), `spots`, `spotR`, `roadHalfWidth` and `workshopR`. With several routes an enemy picks one at random at spawn (`e.route`); routes simply overlap where the road is shared. The waves are the same on every level. `view.levelDef` (what `level()` returns) is the level as played.
- Level generator: a `recipe` entry (`hem`: `zigzag 2, fork pin`, `seed` 3) is built by levelGen.js and painted by levelArt.js; `random: true` (Random Quilt) gets a new `randomRecipe` from each run's seed (startGame rebuilds it and main.js re-runs the resize chain through `setLevelHook`), so `?seed=` replays it. `?recipe=` adds a temporary `custom` level. Generated levels keep the plate size (941×1672), start at the top and end on the heart pad above the action bar; the road stays in `xMin..xMax` and pads in `spotXMin..spotXMax` so a 360px-wide phone (which crops the sides) still shows them. Recipes that don't fit get their last segments dropped, too-close roads and short pad counts are warnings (console, and in the lab).
- Towers ("Pins" in the UI; `CONFIG.towers`) set up snips; the Fire and Needle Pins are the exceptions that deal damage. They can only stand on the level's spots (`level().spots`, one Pin each; `state.towers[i]` is spot i). Building: tap the + on an empty spot, then a card in the picker beside it. Radii are in level units (`towerReach(type)` = px). Ice Pin: enemies in its radius move at `slowSpeedMult` and are `slowed`. Fire Pin: enemies in its radius catch fire (`e.burning`, drawn with flames) and keep burning `burnSec` after leaving it, taking `burnDps` HP/s every `burnTickMs` (ignores armor; orange damage numbers). Burn kills score and pay thread but don't charge SHRED. Needle Pin (the archer): when reloaded and an enemy is in its radius, fires one needle at the one furthest along the road (`damage`), then reloads for `cooldownSec`. Needles home on their target at `needleSpeed` level units/s (a needle whose target died flies on `needleLostSec`, then vanishes); armor stops one like a snip (the first hit on an unslowed Brute clangs, the armor is spent either way); kills score and pay thread but don't charge SHRED; silver damage numbers. Magnet Pin: every `periodSec`, tweens the road progress `u` of enemies in its radius toward the Pin's road point on their own route (`fu[route]`), leaving `pullKeep` of the gap on the stretch of road nearest the Pin and progressively more toward the ring's edge (`pullFalloff`; nothing at the edge; its aura fades the same way), so the ones ahead are dragged back and the ones behind hauled forward into a lasting clump (`e.pulling` while the tween owns `u`/`ox`/`oy`; inOutSine; tagged by the enemy so a kill cancels it).
- Helicopter special (SHRED): charged by `heliKillsToCharge` kills (not during a spin). Trigger: tap the full SHRED meter to arm it (`heli.armed`), then the next press on the table (`heli.go`, from input's `onPress`) starts it once the scissors are there; E, or one more finger while gripping (the 2nd in Hold, the 3rd in Pinch), fires it at once. Its charge meter is the vertical SHRED meter in the bottom-right corner. Snaps open, spins `heliSpinTurns` turns, damages everything in blade reach every `heliTickMs` (ignores armor, slows), then snaps shut into a normal full-open snip. The hand moves the pivot but not spread or aim; normal snips are ignored while it runs.
- Run reports: `endGame` builds `lastReport` (seed, waves, score, snips, kills, accuracy, multi-snips, towers, specials, leaks, duration, userAgent, the six debug values, replay link) and saves it via runlog.js. No analytics or network calls; Send feedback only opens `FEEDBACK_URL` (a `mailto:` draft carrying the run report; nothing is sent without the player pressing Send in their mail app).
- Bosses (`CONFIG.bosses`, rules in game.js's bosses section) only come on boss levels, as the last wave alone: L4 Seam Ripper (reward War Nippers), L8 Brute King (Ratchet Pruners), L12 The Unstitcher (credits). The wave opens on a two-line intro card (name + taunt, `bossIntroMs`) with the boss's own ZzFX roar, and the boss walks on as it closes; its HP bar runs across the top. Each tests one skill, by mode (`bossMode(e)`): `seam` (timing): walks the road back and forth (`bossTurns`); every `seamEverySec` its seam splits open for `seamOpenSec` (a shimmer before, a chirp as it opens): snips then do a flat `openDmg`, otherwise `closedDmg`; in Pinch (Expert) the closed-blade line must also cross the seam (`seamHitTolPx` of the arc) or it does `expertOffSeamDmg`. `armor` (timing + patience): armored and walking forward; every `chargeEverySec` it lunges `chargePx` along the road, then its armor is down for `armorDownSec` (seams glow): snips do `armorDownMult` x graded damage, with the armor on they clang. `swarm` (Unstitcher phase 1): every `swarmEverySec` it calls Scraps that escort it (`e.escortOf`, kept `swarmGapPx` apart around it); only a snip with `multiMin`+ enemies in its zone hurts it. The Unstitcher switches swarm -> armor -> seam (faster) at `phaseAt`. Bosses can't be shoved or slowed (Ice, SHRED), their HP isn't scaled per wave, and fire / needles / SHRED are blocked where the mode blocks snips (`bossBlocks`).
- Kills of tier 2+ trigger a whole-world hit-stop (`hitStopMs`, boss `bossHitStopMs`). Input keeps running through it. Every kill adds screen shake proportional to the enemy's radius. Both run on game.js's real-time tween group, and fragment fades on the world group; a frame is frozen if `fx.hitStop` was still > 0 when it started.
- The level is a painted plate (`level()`): drawn full height and centred, so level units → screen px is `view.L = H / level.h`, offset `view.LX`. Each of `level.paths` (in plate pixels, traced along the painted road) is rebuilt into a Catmull-Rom polyline on resize. Enemy radii and weapon reach are still in screen px, not level units. Enemies store progress `u` (0..1) along their route and advance at `1 / traverseSec`. Shoves are an offset (`ox`, `oy`) that springs back to the road at `pathReturnRate`, capped at `level.roadHalfWidth` from the centreline (`keepOnRoad`), so nothing can be shoved off the road.
- An enemy reaching the workshop deals its size `tier`. A kill scores the size's `score`, times `multiSnipMult` when the snip's zone held at least `multiSnipMin` enemies (survivors count toward that).
- Snips, too-slow shakes and blade contact only happen in PLAYING / WAVE_CLEAR / TUTORIAL.
- Level 0 ("First Snip", `CONFIG.tutLevel`, mode TUTORIAL) is a no-text tutorial for Hold (easy) controls: `setEasyOnly` forces Hold whatever the setting, Dagger Shears, one straight road, no Pins / thread / SHRED / wave badge (the HUD shows only the hearts), no floating words, and nothing hurts the heart (a Scrap that reaches it goes back to the top). A ghost hand (`state.tut.ghost`, drawn by render.js) demonstrates each step, repeating every `tutGhostCycleMs` and holding longer and bigger each repeat (`tut.rep`); it hides while the player presses and returns `tutGhostReturnMs` after a lift that didn't pass. Steps: 1 touch; 2 hold `tutHoldSec` until the blades open (a ring fills round the finger), then lift; 3 cut three frozen Scraps (they walk into empty blades); 4 one wide cut (`tutWideMin`+ at once, opened `tutWideSpread`+) on a row of six, then one short cut (under `tutShortSpread`) on two Scraps far apart; 5 `tutFinishCount` Scraps walk the road; all cut = cleared. A small skip arrow skips a step. Clearing it sets `tutorialDone`, records the level (its reward, Dagger Shears, queues the map's reveal) and opens the MAP. PLAY goes straight to level 0 until `tutorialDone`; How to play and patch 0 on the map replay it.
- Sound: every sound is triggered from game.js through audio.js; the AudioContext is resumed on the first menu-button click.

## Rules

- **Buttons are earned only from performance and achievements. Nothing in the game waits on a clock. No reward is random. Scissors, pins and stars are never purchasable.**
- **Never put a cooldown on the base snip; the player's fingers are the cooldown.**
- **All tunable numbers live in `src/config.js`, each with a one-line comment,** except level data, which lives in `src/levels/` (one file per level, loaded through `loadLevel`). Modules read `CONFIG` at runtime, so the debug panel can change values live. Don't copy config values into module-level constants.
- **No npm, no bundler, no CDN. Third-party code is vendored into vendor/ with its license, and must be under 5KB each.** Plain ES modules via `<script type="module">`, no build step.
- **The scissors' cutting zone must never be occluded by the player's fingers; blades extend away from the finger midpoint.** The pivot sits `pivotOffsetPx` above the finger midpoint, and the blades point perpendicular to the finger line, away from the hand.

## Conventions

- Hot loop: no per-frame allocations. Entities are pooled (`on` flag); snip history is a typed-array ring buffer.
- Snip detection reads the raw finger spread; rendering reads the smoothed `pose`. A close that started wide open (≥ `snipOpenFrom`) but took longer than `slowLookbackMs` still reports "too slow" (tracked by `openPeak` in input.js) instead of being ignored.
- Debug panel: long-press the top-right corner for 1.5s. "Reset defaults" restores `config.js` values and clears localStorage. If feel seems off, check the panel for a stale override first.
